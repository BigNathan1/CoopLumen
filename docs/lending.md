# Peer-to-Peer Lending API & Escrow Mechanism

## Overview

CoopLumen Phase 2 enables community members to request, fund, and repay peer-to-peer loans backed by escrow and reputation scoring derived from repayment history.

## Data Model (`loans`, `loan_repayments`, `reputation_scores`)

### `loans` table

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key, generated by `gen_random_uuid()` |
| `community_id` | UUID | Foreign key to `communities(id)` |
| `borrower_address` | TEXT | Stellar address of the borrower |
| `lender_address` | TEXT | Stellar address of the lender (community issuer for pool loans) |
| `amount` | NUMERIC(20,7) | Principal amount requested |
| `amount_repaid` | NUMERIC(20,7) | Total amount repaid, defaults to 0 |
| `interest_rate` | NUMERIC | Flat interest rate as percentage (e.g., 5 = 5%) |
| `asset_code` | TEXT | Stellar asset code (e.g., `USDC`, `XLM`) |
| `asset_issuer` | TEXT | Stellar asset issuer address, nullable for native XLM |
| `purpose` | TEXT | Optional loan purpose/description |
| `status` | TEXT | Lifecycle state: `pending`, `active`, `overdue`, `repaid`, `defaulted`, `cancelled` |
| `due_at` | TIMESTAMPTZ | Optional repayment due date |
| `disbursed_at` | TIMESTAMPTZ | Timestamp when loan was funded/disbursed |
| `closed_at` | TIMESTAMPTZ | Timestamp when loan reached terminal state |
| `escrow_balance_id` | TEXT | Stellar claimable balance ID for escrow |
| `created_at` | TIMESTAMPTZ | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Last update timestamp (auto-maintained) |

**Derived fields in API responses:**
- `total_due`: Principal + interest (`amount * (1 + interest_rate/100)`)
- `outstanding`: `total_due - amount_repaid`

### `loan_repayments` table

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key |
| `loan_id` | UUID | Foreign key to `loans(id)` with CASCADE DELETE |
| `payer_address` | TEXT | Stellar address making the repayment |
| `amount` | NUMERIC(20,7) | Repayment amount |
| `stellar_tx_hash` | TEXT | Optional Stellar transaction hash |
| `metadata` | JSONB | Optional metadata (e.g., note) |
| `created_at` | TIMESTAMPTZ | Repayment timestamp |

### `loan_events` table

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key |
| `loan_id` | UUID | Foreign key to `loans(id)` with CASCADE DELETE |
| `event_type` | TEXT | One of: `created`, `disbursed`, `repayment`, `closed`, `defaulted` |
| `amount` | NUMERIC(20,7) | Amount associated with event |
| `payment_id` | UUID | Optional reference to `loan_repayments(id)` |
| `note` | TEXT | Optional note |
| `created_at` | TIMESTAMPTZ | Event timestamp |

### `reputation_scores` table

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key |
| `stellar_address` | TEXT | Member's Stellar address |
| `community_id` | UUID | Foreign key to `communities(id)` with CASCADE DELETE |
| `score` | NUMERIC(5,2) | Computed reputation score (0-100) |
| `total_loans` | INTEGER | Total loans taken |
| `on_time_repayments` | INTEGER | Count of on-time repayments |
| `defaults` | INTEGER | Count of defaulted loans |
| `last_calculated_at` | TIMESTAMPTZ | When score was last computed |
| `created_at` | TIMESTAMPTZ | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Last update timestamp (auto-maintained) |

**Unique constraint:** `(stellar_address, community_id)`

**Score calculation:** `(on_time_repayments / total_loans) * 100`, rounded to 2 decimals. With no loan history, score defaults to 50 (neutral).

## Escrow Mechanism

1. **Loan Request Creation:** Borrower submits loan terms via `POST /api/v1/loans/request` (pool loan) or `POST /api/v1/loans` (direct loan). No funds are locked at this stage; loan status is `pending`.

2. **Escrow Lock on Funding (Disbursement):** Lender calls `POST /api/v1/loans/:id/disburse`. Backend creates a Stellar **claimable balance** (`createLoanEscrow`) locking the lender's funds. The borrower can claim this balance once the loan is active. On success, loan status transitions to `active`, `disbursed_at` is set, and `escrow_balance_id` records the claimable balance ID.

3. **Disbursement & Repayment:** Borrower repays via `POST /api/v1/loans/:id/repay`. Each repayment creates a `loan_repayments` record, updates `amount_repaid`, and when `amount_repaid >= total_due`, loan status becomes `repaid` and `closed_at` is set. On-time repayments increment the borrower's `on_time_repayments` counter in `reputation_scores`.

4. **Default Handling:** Lender can mark an overdue `active` loan as `defaulted` via `POST /api/v1/loans/:id/default`, or the automated job `POST /api/v1/loans/detect-defaults` transitions overdue loans. Defaults increment the `defaults` counter in `reputation_scores`.

5. **Cancellation:** Borrower or lender can cancel a `pending` loan via `DELETE /api/v1/loans/:id`.

## API Endpoints

All endpoints are under `/api/v1` and return the standard envelope:
```json
{ "data": <T>, "meta": <PaginationMeta>, "error": <string|null> }
```

| Method | Endpoint | Purpose | Auth / Notes |
|--------|----------|---------|--------------|
| `POST` | `/loans/request` | Create a community pool loan request | Authenticated active member; body: `{ communityId, amount, purpose?, dueAt, interestRate? }` |
| `POST` | `/loans` | Create a direct loan request | Authenticated borrower or lender; body includes `borrowerAddress`, `lenderAddress`, `assetCode`, etc. |
| `GET` | `/loans` | List all loans (paginated, filterable) | Query: `page`, `limit`, `communityId`, `borrower`, `lender`, `status`, `sortBy`, `order` |
| `GET` | `/loans/borrower/:address` | List loans for a borrower | Paginated, newest first |
| `GET` | `/loans/:communityId` | List community loans grouped by status | Path: `communityId`; Query: `status` (`active`\|`pending`\|`closed`), `page`, `limit` |
| `GET` | `/loans/:id` | Fetch loan detail with events & totals | Returns `{ loan, events }` with computed `total_due` and `outstanding` |
| `GET` | `/loans/:id/events` | Chronological event log for a loan | Paginated |
| `POST` | `/loans/:id/disburse` | Fund loan into escrow (create claimable balance) | Authenticated lender only; body: `{ stellarTxHash?, note? }` |
| `POST` | `/loans/:id/repay` | Record a loan repayment | Authenticated borrower only; body: `{ amount, paymentId?, note? }` |
| `POST` | `/loans/:id/default` | Mark loan as defaulted | Authenticated lender only; body: `{ note? }` |
| `POST` | `/loans/detect-defaults` | Automated default detection for overdue loans | Authenticated; returns list of defaulted loans |
| `DELETE` | `/loans/:id` | Cancel a pending loan | Authenticated borrower or lender |

| Method | Endpoint | Purpose | Auth / Notes |
|--------|----------|---------|--------------|
| `GET` | `/reputation` | Paginated reputation leaderboard | Query: `page`, `limit`, `communityId`, `sortBy`, `order` |
| `GET` | `/reputation/:address` | Fetch reputation score & history for address | Optional `communityId` query; returns `{ address, score, communities[], history[] }` |

## Status Codes

| Code | Meaning |
|------|---------|
| `200` | Success (GET, POST updates) |
| `201` | Created (loan request, disbursement) |
| `400` | Bad request (validation error, repayment exceeds outstanding) |
| `401` | Unauthorized (missing/invalid session) |
| `403` | Forbidden (not member, not borrower/lender) |
| `404` | Not found (loan, reputation) |
| `409` | Conflict (wrong loan status for action) |
| `422` | Unprocessable (Zod validation) |
| `429` | Too many requests (rate limited) |
| `500` | Internal server error |
| `502` | Bad gateway (Horizon/Stellar error mapped) |

## Error Responses

```json
{ "data": null, "error": "Descriptive error message", "meta": { "outstanding": "100.0000000" } }
```

Common errors:
- `Loan not found` (404)
- `An active community membership is required to request a pool loan` (403)
- `Only the lender can disburse this loan` (403)
- `Only the borrower can repay this loan` (403)
- `Cannot disburse a loan in status "active"` (409)
- `Repayment exceeds outstanding balance` (400, with `meta.outstanding`)
- `No reputation found for this address` (404)
